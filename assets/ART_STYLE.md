# assets/ART_STYLE.md — 도트 아트 스타일 가이드

`design.md`/`CLAUDE.md`처럼 계속 참고하는 기준 문서다. **스프라이트를 만들거나 수정하는
세션은 작업을 시작하기 전에 이 문서를 반드시 먼저 읽고 그대로 따른다.** (근거:
`inbox.md` #8 — 세션마다 기억이 없는 상태로 시작하므로, 스타일이 이 문서로 고정돼
있지 않으면 스프라이트마다 그림체가 제각각이 되어 "전체적으로 디자인의 느낌이
비슷해야 한다"는 사용자 요구를 지킬 수 없다.)

스타일을 바꾸고 싶으면 `inbox.md`에 근거와 함께 지시 → 승인 후 이 문서를 최소
수정한다. 세션이 스스로 판단해서 스타일을 바꾸지 않는다 (`design.md`와 동일한
원칙).

## 시점 (perspective)

정통 탑다운(카메라가 위에서 수직으로 내려다보는 시점). 아이소메트릭/쿼터뷰가
아니다 — 지금까지 만들어진 모든 절차적 스프라이트(플레이어/동물/나무/식물/
물고기)가 옆에서 본 형태를 그대로 위에서 내려다보는 방식으로 그려져 있고,
`Camera2D`도 회전/기울임 없이 순수 2D 탑다운으로 동작한다. 새 도트 그림도 이
관례를 따른다.

## 캔버스 / 해상도 규칙

- 기본 그리드 단위는 8px. **새로 만드는 캔버스 크기는 항상 8의 배수**(8, 16, 24,
  32, 40, 48, 56, 64 …)로 잡는다.
- 기준 스케일: 플레이어 캐릭터 1명 = 32×32px = world 타일 1칸. 다른 대상의
  캔버스 크기는 이 기준과 비교한 상대적 크기로 정한다.
- 카테고리별 권장 캔버스 크기 (현재 절차적 사각형이 이미 쓰고 있는 크기를
  그대로 기준으로 삼는다 — `player.gd`/`animal.gd`/`tree.gd`/`plant.gd`/
  `fish.gd` 참고):
  | 카테고리 | 권장 크기 | 비고 |
  |---|---|---|
  | 캐릭터(플레이어) | 32×32 | 1 world 타일 |
  | 동물 | 32~48 × 24~40 | 종/등급에 따라 가변, 8의 배수 유지 |
  | 나무 | 48×64 | 세로로 긴 형태 |
  | 식물 | 24×32 | **주의: 현재 `plant.gd`는 28×28을 쓰는데, 이 가이드가
    생기기 전에 만들어져 8의 배수 규칙에서 벗어나 있다. 절차적 사각형을 실제
    도트 그림으로 교체할 때(inbox #8 5번 이후) 24×32나 32×32처럼 8의 배수로
    맞춘다 — 지금 당장 코드를 고치는 건 이 세션의 범위(스타일 문서 작성)를
    벗어난다.** |
  | 물고기 | 32~48 × 16~24 | 가로로 긴 형태 |
  | 아이템 아이콘(인벤토리/핫바) | 16×16 | 슬롯 안에 작게 표시되는 용도 |
- 그림은 최종 해상도로 직접 그린다(작게 그려서 확대하지 않는다). Godot에서
  표시할 때는 텍스처 필터를 **Nearest**로 둬서 확대돼도 픽셀 경계가 흐려지지
  않게 한다(`project.godot`의 기본 렌더링 설정 또는 개별 `CanvasItem` 노드의
  `texture_filter`).

## 색상 팔레트

- 게임 전체가 공유하는 제한된 팔레트를 벗어나지 않는다. 새 소재(재질) 색을
  추가할 때도 아래처럼 **기본색 1 + 그림자색 1 + 밝은색 1**의 3톤 규칙을
  따른다:
  - 그림자색 = 기본색의 명도(V) −20%, 채도(S) +5%
  - 밝은색 = 기본색의 명도(V) +15%
  - (HSV 기준. Pillow로 절차 생성할 때 `colorsys.rgb_to_hsv`/`hsv_to_rgb`로
    기계적으로 계산 가능 — inbox #8 2번에서 만들 생성 도구가 이 공식을 그대로
    구현한다.)
- 그라디언트·안티앨리어싱 금지. 색과 색의 경계는 항상 뚜렷한 계단(hard edge)
  이어야 한다. Pillow에서 리사이즈/회전 시 보간(interpolation)이 들어가면 이
  규칙이 깨지므로, 리사이즈가 필요하면 `Image.NEAREST`만 쓴다.
- 기존 코드에 이미 박혀 있는 대표색은 새 팔레트의 앵커로 그대로 쓴다(임의로
  바꾸지 않는다):
  | 소재 | 기본색 (RGB 0~1) | 출처 |
  |---|---|---|
  | 피부(기본) | (0.2, 0.6, 1.0) | `player.gd DEFAULT_SKIN_COLOR` |
  | 눈(기본) | (0.05, 0.05, 0.05) | `player.gd DEFAULT_EYE_COLOR` |
  | 머리— short | (0.25, 0.15, 0.05) | `player.gd HAIR_STYLES` |
  | 머리 — mohawk | (0.05, 0.05, 0.05) | `player.gd HAIR_STYLES` |
  | 기본 복장(하의) | (0.35, 0.25, 0.15) | `player.gd OUTFIT_COLOR` |
  | 나무 줄기 | (0.45, 0.3, 0.15) | `tree.gd` |
  | 나뭇잎 | (0.15, 0.5, 0.2) | `tree.gd` |
  | 식물 잎 | (0.3, 0.7, 0.25) | `plant.gd` |
  | 식물 줄기/흙 | (0.55, 0.35, 0.15) | `plant.gd` |
  | 동물(기본) | (0.6, 0.4, 0.2) | `animal.gd` |
  | 물고기 | (0.3, 0.55, 0.8) | `fish.gd` |
  | 바다 | (0.2, 0.5, 0.8) | `terrain.gd` |
  | 모래(해변) | (0.85, 0.75, 0.5) | `terrain.gd` |
  | 섬(땅) | (0.35, 0.65, 0.25) | `terrain.gd` |

## 외곽선

외곽선 없음. 지금까지 만들어진 모든 절차적 스프라이트가 외곽선 없이 면 색과
명암만으로 형태를 구분해왔으므로, 실제 도트 그림으로 교체해도 이 기준을
유지해야 같은 화면에서 시각적으로 튀지 않는다. 실루엣을 더 또렷하게 하고
싶으면 외곽선 대신 그림자 톤 1px 라인을 안쪽 경계에 쓰는 것은 허용한다.

## 광원 방향

좌상단 45도 고정. 밝은 면은 좌상단, 그림자는 우하단에 둔다. 모든 스프라이트가
동일한 광원 가정을 공유해야 여러 오브젝트가 한 화면에 놓였을 때 조명이
제각각으로 보이지 않는다.

## 애니메이션 규칙 (움직이는 대상)

- 걷기처럼 반복되는 동작은 최소 4프레임(예: 대기-좌족-대기-우족의 좌우대칭
  사이클)으로 시작하고, 필요하면 프레임 수를 늘린다.
- 프레임마다 캔버스 크기·팔레트가 같아야 하고, 비례(머리 크기·몸통 폭 등)가
  프레임 사이에서 흔들리면 안 된다. 걷기 바운스처럼 세로 위치가 움직이는 연출은
  허용하되 진폭을 ±2px 이내로 제한한다.
- 프레임 스트립을 이어 붙여 Read 도구로 직접 보고 자연스러움을 판단하는 절차는
  `inbox.md` #8 4번(다음 세션 이후 만들 도구)이 담당한다 — 이 문서는 규칙만
  정의하고 도구 자체는 아직 없다.

## 파일 구성 규칙

- 최종 채택된 스프라이트: `assets/sprites/<category>/<name>.png`
  (예: `assets/sprites/player/body_base.png`). 카테고리는 `player`, `animal`,
  `tree`, `plant`, `fish`, `item`, `ui` 중에서 고른다.
- 후보 비교용으로 생성한 이미지(10장 후보, 비교 그리드 등)는 최종 채택본이
  아니므로 저장소에 커밋하지 않는다 — `inbox.md` #8 2번에서 생성 도구를 만들
  때, 후보 산출물 경로를 `.gitignore`에 함께 추가한다.

## 아직 정해지지 않음

- 구체적인 팔레트 색상 수 상한(예: 대상당 최대 8색), 아이템 아이콘의 세부
  형태 규칙은 실제로 첫 도트 그림(플레이어, inbox #8 5번)을 만들어보면서
  구체화한다 — 지금 미리 숫자를 확정하면 실제 그림 결과와 맞지 않을 수 있어,
  상식적인 선의 원칙만 이번에 정하고 세부는 다음 단계에서 다듬는다.
